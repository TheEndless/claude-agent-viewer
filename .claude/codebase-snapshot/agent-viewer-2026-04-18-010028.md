## Project Overview

Agent Viewer (v0.0.1) is a VS Code extension that provides a sidebar panel for monitoring running and past Claude Code agent sessions on the local machine. It watches `~/.claude/projects/**/*.jsonl` transcript files written by Claude Code, parses them for session state and activity, and renders a grouped list of agents (Running / Idle / Done) with per-agent details and actions.

Target users: developers running Claude Code agents who want visibility into what each agent is doing without switching terminal windows. The extension is private/personal — no marketplace listing currently.

## System & Feature Inventory

### 1. Agent State Machine
**File:** [src/agentService.ts:148-153](src/agentService.ts#L148-L153)

Three states: `running` (file modified within last 10s), `idle` (10s–24h since modification), `done` (>24h since modification OR a `summary`-type event found in transcript). State is re-evaluated on every file change event AND on a 5-second periodic tick (`reclassifyAll`).

### 2. Transcript File Watcher
**File:** [src/agentService.ts:31-43](src/agentService.ts#L31-L43)

Uses chokidar to watch `~/.claude/projects/**/*.jsonl`. Configuration: `ignoreInitial: false` (processes existing files on start), `awaitWriteFinish` with 100ms stability threshold. Handles `add`/`change` → `refreshFile()`, `unlink` → `dropFile()`. Session ID = basename without `.jsonl`.

### 3. Transcript Tail Reader + JSONL Parser
**File:** [src/agentService.ts:71-95](src/agentService.ts#L71-L95)

Reads only the last 64KB (`TAIL_BYTES`) of each transcript for performance — O(1) I/O regardless of transcript length. Splits on newlines, drops the first line when reading mid-file (partial line), parses each line as JSON, silently skips malformed lines. Keeps only the last 20 events (`KEEP_EVENTS`).

### 4. Agent Builder
**File:** [src/agentService.ts:123-132](src/agentService.ts#L123-L132)

`buildAgent()` constructs a full `Agent` object from file path, mtime, and parsed events. Orchestrates: session ID from path, CWD resolution, state classification, activity derivation, and detail extraction.

### 5. Activity Derivation
**File:** [src/agentService.ts:161-218](src/agentService.ts#L161-L218)

Scans events in reverse to find the most recent non-noise event and maps it to a human-readable string. Tool use events produce labels like `Bash: git status`, `Edit main.ts`, `Reading config.json`, `Subagent: description`. Text parts → "Thinking". Tool results → "Processing tool result". Noise events (`queue-operation` type) are skipped. Falls back to "Working…" or "Idle".

### 6. Agent Details Extractor
**File:** [src/agentService.ts:227-261](src/agentService.ts#L227-L261)

Scans all events to build `AgentDetails`: last 5 tool call summaries with timestamps (newest-first), last 5 unique file paths touched (deduped via reverse scan), latest user prompt text (truncated to 200 chars, last non-empty text part in multi-part messages), subagent count (count of `Agent` tool uses).

### 7. CWD Resolution
**File:** [src/agentService.ts:138-146](src/agentService.ts#L138-L146)

Prefers `cwd` field from any event in the transcript. Falls back to decoding the parent directory name (Claude Code encodes paths as dash-separated directory names). Code comments this fallback as lossy — dashes ambiguously map to path separators.

### 8. Debounced Event Emission
**File:** [src/agentService.ts:97-100](src/agentService.ts#L97-L100)

After any file change, schedules `_onDidChange.fire(getAgents())` with a 200ms debounce (`DEBOUNCE_MS`) to coalesce rapid file system events into a single UI update.

### 9. WebviewViewProvider
**File:** [src/webviewProvider.ts:9-156](src/webviewProvider.ts#L9-L156)

Implements `vscode.WebviewViewProvider` for view ID `agentViewer.panel`. On `resolveWebviewView`: enables scripts, registers message handler, subscribes to `agentService.onDidChange`, starts/stops 5s auto-refresh timer based on panel visibility, injects the HTML page. Visibility change also immediately re-sends agents when the panel becomes visible.

### 10. Embedded Webview UI
**File:** [src/webviewProvider.ts:158-605](src/webviewProvider.ts#L158-L605)

A self-contained HTML/CSS/JS page injected as a template literal string. Uses VS Code CSS custom properties for theming (no hardcoded colors except status dots). Key UI elements:
- **Header**: "Agents" title + pulsing green auto-refresh indicator
- **Three collapsible sections** (`<details>`) for Running / Idle / Done, with count badges. Open/closed state preserved in `openSections` JS object across re-renders
- **Agent cards**: colored status dot (green glow for running, amber for idle, grey for done), project name, activity string, relative timestamp. Hover reveals action buttons
- **Expand/collapse**: click card body to toggle `card-details` div showing working directory, last activity time, latest user prompt, recent tool calls trail (with relative timestamps), recent files list, subagent count
- **Action buttons** (appear on hover): view transcript (📄), open folder (📁), stop (■, running only), delete (✕)
- **All rendering**: string template concatenation, `root.innerHTML` replacement on each render. No virtual DOM or diffing

### 11. Message Bridge (Extension ↔ Webview)
**File:** [src/webviewProvider.ts:48-82](src/webviewProvider.ts#L48-L82)

**Extension → Webview**: `postAgents()` serializes agents (subset of fields, no transcriptPath) and sends `{ command: 'render', agents, now: Date.now() }`.
**Webview → Extension**: user actions send `{ command: string, sessionId: string }` via `vscode.postMessage()`. `handleMessage()` routes: `viewTranscript`, `openFolder`, `stop`, `delete`.

### 12. View Transcript Action
**File:** [src/webviewProvider.ts:84-91](src/webviewProvider.ts#L84-L91)

Opens the `.jsonl` transcript file in the VS Code editor as a preview tab via `vscode.workspace.openTextDocument` + `vscode.window.showTextDocument`.

### 13. Open Folder Action
**File:** [src/webviewProvider.ts:93-96](src/webviewProvider.ts#L93-L96)

Executes `vscode.openFolder` command with `forceNewWindow: true` pointing at `agent.cwd`.

### 14. Stop Agent Action (POSIX only)
**File:** [src/webviewProvider.ts:98-128](src/webviewProvider.ts#L98-L128) + [src/processService.ts](src/processService.ts)

Calls `findAgentPids(cwd)` to find matching Claude processes. If none: warning message. If one: confirms via modal then `killAgent(pid)` (SIGTERM). If multiple: user picks via `showQuickPick` first. On Windows: always returns empty — action silently shows "No running Claude process found."

`findAgentPids()` uses `ps -Ao pid=,args=` to list all processes, filters for "claude" in args (excludes VS Code extension host/code-helper processes), then uses `lsof -a -p <pid> -d cwd -F n` to verify each candidate's CWD matches.

### 15. Delete Transcript Action
**File:** [src/webviewProvider.ts:130-144](src/webviewProvider.ts#L130-L144)

Modal confirmation dialog, then `fsp.unlink(transcriptPath)`. The chokidar `unlink` handler then automatically removes the agent from the in-memory map and fires `onDidChange`.

### 16. Extension Lifecycle
**File:** [src/extension.ts](src/extension.ts)

`activate()`: creates `AgentService`, calls `start()`, creates `AgentWebviewProvider`, registers webview provider + `agentViewer.refresh` command + dispose hook in `context.subscriptions`. `deactivate()` is a no-op (cleanup via disposables).

## Data Models

### AgentState
```typescript
type AgentState = 'running' | 'idle' | 'done';
```

### Agent
```typescript
interface Agent {
  sessionId: string;        // basename of .jsonl file (no extension)
  transcriptPath: string;   // absolute path to .jsonl file on disk
  cwd: string;              // working directory of the agent session
  projectName: string;      // path.basename(cwd)
  state: AgentState;
  activity: string;         // human-readable current activity string
  mtimeMs: number;          // file modification time (ms since epoch)
  pid?: number;             // declared but never populated (reserved placeholder)
  details: AgentDetails;
}
```

### AgentDetails
```typescript
interface AgentDetails {
  recentToolCalls: ToolCallSummary[];  // last 5 tool calls, newest-first
  recentFiles: string[];               // last 5 unique file paths touched, newest-first
  latestUserPrompt: string | null;     // truncated to 200 chars
  subagentCount: number;               // count of Agent tool uses in scanned events
}

interface ToolCallSummary {
  summary: string;  // human-readable label (same as activity derivation)
  at: number;       // ms since epoch (from event timestamp)
}
```

### RawEvent
```typescript
interface RawEvent {
  type?: string;            // e.g. 'assistant', 'user', 'summary', 'queue-operation'
  timestamp?: string;       // ISO 8601 string
  sessionId?: string;
  cwd?: string;
  message?: {
    role?: string;
    content?: unknown;      // string or array of content parts
  };
  [key: string]: unknown;   // arbitrary additional fields
}
```

### Webview Message Protocol (no dedicated TypeScript type)
- **Extension → Webview**: `{ command: 'render', agents: Agent[], now: number }`  
  (agents are serialized without `transcriptPath`)
- **Webview → Extension**: `{ command: string, sessionId: string }`  
  Commands: `'viewTranscript'`, `'openFolder'`, `'stop'`, `'delete'`

## Architecture & Flow

```
~/.claude/projects/**/*.jsonl
          │
          │  chokidar (add / change / unlink)
          ▼
     AgentService
       ├─ refreshFile(path)
       │    ├─ fsp.stat() → mtimeMs
       │    ├─ tailEvents() → read last 64KB, parse JSONL, last 20 events
       │    └─ buildAgent() → classifyState, deriveActivity, extractDetails
       │         └─ agents Map<sessionId, Agent>
       ├─ dropFile(path) → delete from map
       ├─ reclassifyAll() [5s tick] → re-check state by mtime age
       └─ scheduleEmit() [debounced 200ms] → _onDidChange.fire(getAgents())
                │
                │  onDidChange subscription + 5s auto-refresh timer
                ▼
     AgentWebviewProvider
       └─ postAgents() → webview.postMessage({ command: 'render', agents, now })
                │
                │  VS Code WebviewView message bridge
                ▼
     Webview (embedded HTML/JS)
       ├─ window.message → render(agents, now)
       │    └─ group by state → renderSection → renderCard × N → root.innerHTML
       └─ user action → vscode.postMessage({ command, sessionId })
                │
                │  handleMessage(message)
                ▼
         viewTranscript  → vscode.workspace.openTextDocument
         openFolder      → vscode.commands.executeCommand('vscode.openFolder')
         stop            → processService.findAgentPids() + killAgent(pid)
         delete          → fsp.unlink(transcriptPath)
```

### Add a New Tool Label

### Add a New Agent Action
1. Add a button with `data-act="myAction"` in `renderCard()` in webviewProvider.ts
2. Add `case 'myAction':` in `handleMessage()` routing
3. Implement the handler method on `AgentWebviewProvider`

### Known Gotchas
- Process stop is **non-functional on Windows** — `processService.ts` explicitly returns `[]` for `win32`; no Windows implementation exists
- The `pid` field on `Agent` type is declared but never populated anywhere
- CWD fallback (dash-to-slash directory name decoding) is lossy and can produce wrong paths
- Webview HTML is a template literal — no hot reload; must rebuild for UI changes
- `awaitWriteFinish` 100ms threshold may miss very rapid writes in edge cases
- The 64KB tail limit means state for very active long-running agents is derived from recent events only
- Webview expand/collapsed state and section open/closed state live in JS variables — reset if panel is closed and reopened

## Conventions & Patterns

- **No UI framework**: webview uses plain string template concatenation, `root.innerHTML` replacement. No React/Vue/Svelte.
- **Defensive HTML escaping**: all user-derived strings go through `esc()` before HTML insertion — prevents XSS from malicious project names or file paths.
- **Immutable agent updates**: `reclassifyAll()` uses spread `{ ...agent, state: nextState }` not mutation.
- **VS Code EventEmitter pattern**: `AgentService` exposes a typed `onDidChange: vscode.Event<Agent[]>` — consumers subscribe without polling.
- **Disposable pattern**: all timers, watchers, and event subscriptions are cleaned up in `dispose()` or registered in `context.subscriptions`.
- **Tail reading**: reads only the last 64KB per file — constant-time I/O regardless of transcript size.
- **TypeScript strict mode**: enforced via tsconfig; no explicit `any` types in source.
- **Single bundle**: esbuild bundles everything (including chokidar) into one `dist/extension.js` CJS file; `vscode` and `fsevents` are externalized.
